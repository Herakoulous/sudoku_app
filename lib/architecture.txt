CORE DATA MODELS & STRUCTURES
=============================================================================

1) POSITION (models/position.dart)
   PURPOSE: Immutable grid coordinate representation
   
   Properties:
   - int row: Row index (0-8)
   - int col: Column index (0-8)
   
   Methods:
   - Position(row, col): Constructor
   - operator ==(): Coordinate equality for Set/Map usage
   - hashCode: Enables efficient Set/Map operations
   - toString(): Debug representation "Position(row, col)"
   - toJson(): Serialization {"row": row, "col": col}
   - fromJson(): Deserialization from Map<String, dynamic>

2) SUDOKU CELL (models/sudoku_cell.dart)
   PURPOSE: Individual cell state with all properties and behaviors
   
   Core Properties:
   - int row, col: Immutable position coordinates
   - int? number: Main number (1-9 or null for empty)
   - Set<int> sideNotes: Corner pencil marks (1-9)
   - Set<int> centerNotes: Center pencil marks (1-9)
   - Color? cellColor: Background color for organization
   - bool isGiven: Original puzzle number (immutable)
   - bool isSelected: Dark blue selection state
   - bool isHighlighted: Light blue highlight state
   - bool isError: Red border for conflicts
   
   Constructors:
   - SudokuCell(): Default with all parameters
   - SudokuCell.given(): For original puzzle numbers
   - SudokuCell.empty(): For blank cells
   
   State Management:
   - copyWith(): Immutable updates with clearNumber/clearColor flags
   - clear(): Removes all user input (preserves given numbers)
   - toggleSideNote(int): Adds/removes corner note
   - toggleCenterNote(int): Adds/removes center note
   - setNumber(int?): Sets main number, clears notes
   - setColor(Color?): Sets background color
   
   Computed Properties:
   - isEmpty: No content whatsoever
   - hasUserInput: Has user-entered content
   - sortedSideNotes/sortedCenterNotes: Ordered note lists
   
   Serialization:
   - toJson(): Complete state to Map (excludes visual flags)
   - fromJson(): Restoration from Map

3) ACTION SYSTEM (models/action.dart)
   PURPOSE: Comprehensive undo/redo with atomic operations
   
   ActionType Enum:
   - SET_NUMBER: Place/remove main number
   - CLEAR: Erase all cell content
   - TOGGLE_SIDE_NOTE: Add/remove corner note
   - TOGGLE_CENTER_NOTE: Add/remove center note
   - SET_COLOR: Change cell background
   - ERASE_NOTE: Auto-remove conflicting notes
   - GROUP: Placeholder for grouped operations
   
   Action Class:
   - type: ActionType - what operation was performed
   - position: Position - which cell was affected
   - oldCell: SudokuCell - state before change
   - newCell: SudokuCell - state after change
   - timestamp: DateTime - when action occurred
   - groupId: String? - links related actions for atomic undo/redo
   
   ActionGroup Class:
   - actions: List<Action> - related operations
   - timestamp: DateTime - group creation time
   - Enables atomic undo/redo of multi-cell operations

4) GAME STATE (models/game_state.dart)
   PURPOSE: Complete game state management and persistence
   
   Enums:
   - GameMode: NORMAL, SIDE_NOTES, CENTER_NOTES, COLORING
   - SelectionMode: SINGLE, MULTIPLE
   
   Core State:
   - grid: List<List<SudokuCell>> - 9x9 puzzle grid
   - currentMode: GameMode - active input mode
   - selectionMode: SelectionMode - single vs multi-cell selection
   - selectedCells: Set<Position> - currently selected cells
   - highlightedCells: Set<Position> - related cells to show
   
   Game Metadata:
   - puzzleId: String - unique puzzle identifier
   - difficulty: int - star rating (1-10)

   - isPaused: bool - timer state
   - isCompleted: bool - puzzle solved flag
   
   History System:
   - actionHistory: List<Action> - complete undo/redo history
   - currentActionIndex: int - position in history (-1 = no actions)
   
   Variant Support:
   - constraints: List<VariantConstraint> - special puzzle rules
   
   Factory Methods:
   - newGame(puzzleId, difficulty): Creates fresh game from puzzle data
   - _createEmptyGrid(): Helper for 9x9 empty grid
   
   Key Methods:
   - markCompleted(): Sets completion flag
   - isGridComplete(): Checks if puzzle is solved (filled + no errors)
   - elapsedSeconds: Getter for save service
   - currentGrid: Getter for level selection preview
   - toJson()/fromJson(): Complete state persistence

5) VARIANT CONSTRAINTS (models/variant_constraint.dart)
   PURPOSE: Special puzzle rules system
   
   ConstraintType Enum:
   - KROPKI_WHITE: Adjacent cells differ by 1 (consecutive)
   - KROPKI_BLACK: Adjacent cells in 2:1 ratio (double)
   - THERMO: Thermometer constraint (increasing from bulb to tip)
   - XV_X: Sum equals 10 (X)
   - XV_V: Sum equals 5 (V)
   - GERMAN_WHISPERS: Adjacent cells differ by at least 5
   - SANDWICH: Sum between 1 and 9 in row/column
   
   VariantConstraint Class:
   - type: ConstraintType - constraint category
   - row1, col1, row2, col2: Two connected cells (for Kropki, XV, German Whispers)
   - thermoCells: List<Position>? - Full path for thermo constraints
   - sandwichSum: int? - Sum value for sandwich constraints
   - sandwichRow: int? - Row number for sandwich (if row constraint)
   - sandwichCol: int? - Column number for sandwich (if column constraint)
   
   Utility Methods:
   - isBetween(r1,c1,r2,c2): Checks if constraint applies to cell pair
   - involvesCell(row,col): Checks if constraint affects specific cell
   - getOtherCell(row,col): Returns partner cell in constraint
   - orientation: 'horizontal' or 'vertical' getter
   - toJson()/fromJson(): Persistence support

GAME CONTROLLER - CORE BUSINESS LOGIC ENGINE
=============================================================================

game_controller.dart - Central Game Logic (extends ChangeNotifier)
PURPOSE: Manages all game state changes, user interactions, and business rules

CORE RESPONSIBILITIES:

CELL SELECTION SYSTEM:
- handleCellTap(row, col):
  * Single mode: 
    - If tapping already selected cell: Unselects it (clears selection)
    - If tapping different cell: Clears all selections, selects new cell
  * Multiple mode: Toggles cell in/out of selection (add if not selected, remove if selected)
  * Updates gameState.selectedCells Set<Position>
  * Calls updateHighlights() and notifyListeners()

DRAG SELECTION SYSTEM:
- Continuous multi-cell selection by dragging
- Position calculation with padding adjustments  
- Prevents tap events after drag operations
- Visual feedback during drag operation

NUMBER INPUT PROCESSING:
- handleNumberInput(number):
  * NORMAL mode: Sets main number, clears notes
  * SIDE_NOTES mode: Toggles corner pencil marks (keeps center notes)
  * CENTER_NOTES mode: Toggles center pencil marks (keeps side notes)
  * COLORING mode: Sets cell background color
  * Creates Action objects for undo/redo
  * Calls eraseNotesInRelatedCells() for main numbers (if auto-notes enabled)
  * Groups related actions for atomic operations

AUTO NOTE ERASING ALGORITHM:
- eraseNotesInRelatedCells(position, number):
  * Checks SettingsService.getAutoNotes() before erasing
  * Finds all cells in same row, column, and 3x3 box
  * Removes conflicting number from their side and center notes
  * Creates ERASE_NOTE actions for undo support
  * Groups with main SET_NUMBER action using shared groupId
  * Returns List<Action> for grouped operations

CELL ERASURE:
- eraseSelectedCells():
  * Clears all user input from selected cells
  * Preserves original puzzle numbers (isGiven = true)
  * Creates CLEAR actions for undo support
  * Handles single or multiple cells efficiently

VALIDATION SYSTEM:
- validateGrid():
  * Checks SettingsService.getShowMistakes() before showing errors
  * Checks each filled cell for conflicts
  * Row validation: No duplicate numbers 1-9
  * Column validation: No duplicate numbers 1-9
  * Box validation: No duplicates in 3x3 sections
  * Sets isError flag on conflicting cells
  * Real-time feedback on every change
  * Calls _checkIfComplete() when no errors found

COMPLETION CHECKING:
- _checkIfComplete():
  * Checks if all cells are filled
  * Verifies no errors exist
  * Marks puzzle as completed
  * Saves completion status and best time
  * Clears saved game grid (keeps completion status)

HIGHLIGHTING SYSTEM:
- updateHighlights():
  * Single selection: Highlights row + column + box (related cells)
  * Multiple selection: Highlights intersection of all selected cells' related cells
  * Updates isSelected and isHighlighted flags on all cells
  * Provides visual feedback for valid move locations
- getRelatedCells(position): Returns Set<Position> of row+column+box

UNDO/REDO SYSTEM:
- addAction(action): Adds single action to history, removes redo history
- addGroupedActions(actions): Adds related actions with shared groupId
- undo(): Restores previous state, handles action groups atomically
- redo(): Reapplies undone actions, handles action groups atomically
- canUndo()/canRedo(): Checks if operations are available

MODE MANAGEMENT:
- changeMode(GameMode): Switches input mode, notifies listeners
- toggleMultipleSelection(): Toggles between single/multi selection

UTILITY FUNCTIONS:
- getSelectedNumber(): Returns number in selected cell (single selection only)
- countNumber(number): How many times number appears in grid
- isNumberComplete(number): True if number appears 9 times
- restartPuzzle(): Resets to initial state, clears history

PERSISTENCE:
- saveProgress(): Stores current state via SaveService
- loadProgress(): Restores saved state, validates constraints match, updates highlights

TIMER MANAGEMENT:
- startTimer(): Resumes timer
- pauseTimer(): Pauses timer

DATA FLOW ARCHITECTURE
=============================================================================

USER INPUT FLOW:
1. User taps cell → SudokuGrid.onCellTap()
2. Calls GameController.handleCellTap()
3. Updates GameState.selectedCells
4. Calls updateHighlights() → marks related cells
5. Calls notifyListeners() → triggers UI rebuild

NUMBER INPUT FLOW:
1. User taps number → NumberPad button
2. Calls GameController.handleNumberInput()
3. Processes based on currentMode:
   - NORMAL: Sets main number, clears notes
   - SIDE_NOTES: Toggles corner notes (keeps center notes)
   - CENTER_NOTES: Toggles center notes (keeps side notes)
   - COLORING: Sets background color
4. Creates Action for undo/redo
5. If main number and auto-notes enabled: calls eraseNotesInRelatedCells()
6. Calls validateGrid() → checks conflicts
7. Calls notifyListeners() → UI updates

UNDO/REDO FLOW:
1. Action created with oldCell/newCell states
2. Added to actionHistory with optional groupId
3. Undo: Restore oldCell states, decrement index
4. Redo: Restore newCell states, increment index
5. Group actions: Process entire group atomically

PERSISTENCE FLOW:
1. GameState → toJson() → JSON string
2. SaveService.saveGame() → SharedPreferences
3. Load: JSON string → fromJson() → GameState
4. Completion tracking and best times updated
5. Completed puzzles: Grid cleared, status preserved

VALIDATION FLOW:
1. Every number change triggers validateGrid()
2. Checks SettingsService.getShowMistakes()
3. Check cell against row, column, 3x3 box
4. Mark conflicts with isError flag
5. UI shows red borders for invalid cells
6. If no errors and filled: Check completion

SETTINGS FLOW:
1. SettingsScreen loads all settings from SettingsService
2. User toggles setting → SettingsService.setX()
3. SharedPreferences updated
4. GameController reads settings when needed (async)
5. UI updates based on setting values
